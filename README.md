# Прогноз пожарного риска — демонстрационный MVP

Система помогает диспетчеру увидеть опасный объект, перейти к пикету и датчикам,
понять причины прогноза, проверить SMS-оповещение, зафиксировать решение и создать
заявку на профилактические работы.

## Быстрый запуск для жюри

Нужен только Docker Desktop.

```powershell
docker compose up --build -d
```

Контейнер ML загружает обученный артефакт с четырьмя горизонтами прогноза:
сейчас, 6, 12 и 24 часа.

После запуска откройте: **http://localhost:8080**. Интерактивная документация
ML API доступна по адресу **http://localhost:8000/docs**.

Автоматическая проверка стенда:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\smoke.ps1
```

Остановка:

```powershell
docker compose down
```

Полный сброс демонстрационных решений и заявок:

```powershell
docker compose down -v
docker compose up --build -d
```

Текущая роль видна справа вверху. Там же можно переключиться между техником,
диспетчером района, диспетчером ОДС и группой реагирования. В MVP переключатель
показывает перспективу пользователя; полноценная авторизация не подключена.

Подробный текст выступления: [docs/demo-script.md](docs/demo-script.md).

## Как устроено

`docker compose` запускает четыре сервиса:

- PostgreSQL — объекты, каналы, предупреждения, решения, заявки и SMS;
- ML на FastAPI — запуск обученного артефакта и документация OpenAPI;
- API на ASP.NET Core — бизнес-процесс и интеграция с ML;
- WEB на React — интерфейс диспетчера.

Порты:

- WEB: `http://localhost:8080`;
- API: `http://localhost:5000`;
- ML health: `http://localhost:8000/health`.

Страница демонстрации использует ровно 24 полные строки периода test, а не train.
Полные 157 признаков остаются на сервере: браузер получает только понятный контекст
объекта и отправляет идентификатор выбранной записи. Вероятности нигде не заготовлены —
они вычисляются при каждом нажатии «Рассчитать прогноз». Непубликованный результат
хранится в памяти API 30 минут. Публикация и очистка не переобучают и не изменяют модель.

Демонстрационные записи имеют фиксированные идентификаторы и время. После
`docker compose down -v` одинаковый запуск создаёт одинаковые объекты, уровни,
возраст датчиков, историю и SMS.

## Недоступность ML

API сохраняет последний успешный прогноз. Если ML временно недоступен, API
возвращает этот прогноз с признаком `stale=true`, а интерфейс показывает
предупреждение пользователю.

Проверка:

```powershell
docker compose stop ml
Invoke-RestMethod -Method Post -Uri http://localhost:5000/api/objects/demo-object-1/predict `
  -ContentType application/json -Body '{"features":{"activity_ratio_24h":1.25,"alarm_count_5m":3,"smoke_heat_5m":1},"topK":3}'
docker compose start ml
```

## Ограничения MVP

- нет подтверждённых меток реальных пожаров;
- SMS эмулируются и записываются в журнал, реальный провайдер не подключён;
- сведения о возрасте, ТО и работах могут поступать из явно обозначенного demo/mock-источника;
- схема пикетов относительная, это не географическая карта;
- нет промышленной авторизации, отказоустойчивого кластера и интеграции с системами заказчика;
- демонстрационная последовательность конечна и предназначена для воспроизводимого показа; прогнозы при этом рассчитывает подключённый обученный артефакт.
